# WalaOne × Amazon landing page

Bilingual (Arabic-first RTL, English) landing page for the WalaOne × Amazon employee membership. Next.js 15 App Router, Tailwind v4, GSAP scroll choreography, mocked purchase flow.

## Scripts

| Script                | What it does                                                       |
| --------------------- | ------------------------------------------------------------------ |
| `npm run dev`         | Dev server. `/` redirects to `/ar`; `/en` is the English page.     |
| `npm run build`       | Production build.                                                  |
| `npm run check`       | typecheck + eslint + lint:colors + build — the definition of done. |
| `npm run lint:colors` | Fails if any colour is written outside `styles/tokens.css`.        |
| `npm run format`      | Prettier over the tree.                                            |

## Demo triggers (mocked purchase flow)

There is no backend. `lib/mockApi.ts` simulates it with ~700 ms latency. Any six digits pass the identity step and any approved-domain email subscribes, except these deterministic switches:

| Input                               | Where    | Result                                                  |
| ----------------------------------- | -------- | ------------------------------------------------------- |
| `test.pending@amazon.com`           | Details  | "already an active or pending subscription" under email |
| `test.payfail@amazon.com`           | Payment  | first attempt fails (nothing charged), retry succeeds   |
| code `999999`                       | Identity | wrong code                                              |
| code `000000`                       | Identity | expired code (the code itself lasts an hour)            |
| any other `@amazon.com`/`amazon.sa` | —        | happy path → order reference `WO-AMZ-XXXXXX`            |

Accepted email domains live in `APPROVED_DOMAINS` in `lib/validation.ts`; subdomains such as `eu.amazon.com` are accepted. The mobile field is the national number only, since the country block beside it shows `+966`: nine characters at most, and nine digits opening with 5 to pass, stored as E.164. Arabic-Indic digits still count, so a Saudi user typing on an Arabic keyboard is not told their own number is wrong. Each step’s submit button is live only once that step would pass: all four details fields, or all six digits of the code. On the details step that means the summary which used to follow an invalid submit is now reached only by a server error, though the inline errors still appear as each field is left; on the identity step the incomplete-code guard in the handler is now a backstop for a programmatic submit, since a disabled default button also blocks the form’s implicit submission. Validity is read from the schema against what is currently typed rather than from react-hook-form’s isValid, which lags a mode behind under onTouched and would leave a button dead under a finished form. The code and the resend run on two separate clocks in `lib/mockApi.ts`: `OTP_TTL_MS` gives the code an hour, so a user who steps away can still finish, while `RESEND_COOLDOWN_S` locks the resend link for 60 seconds after each code is issued. Because the code now long outlives the cooldown, the expired state is reached in a demo through the `000000` trigger rather than by waiting.

## Brand and re-skinning

Every colour, radius and motion timing lives in `styles/tokens.css`. Change values there and nothing else; components only ever reference token utilities (`bg-bg-hero`, `text-ink-muted`, `rounded-card`, …). `npm run lint:colors` keeps it that way.

The tokens carry the WalaOne brand from the Figma variables (Singular V1.0.0): Primary purple `#755BD8` scale and Secondary yellow `#FAC333` scale, Grey 900/100 for ink and surfaces. Two neutrals are derived and documented in the file: `--color-ink-muted` (`#555070`, because Grey 500 is 2.6:1 on white) and `--color-ink-on-dark-muted` (Primary 100). Yellow is used only on the purple bands (it is 1.6:1 against white); light sections use Primary 600 for buttons and brand UI. The hero surface is an image, not the gradient: `public/hero/spectral.jpg` is the fill of node 3:6 in the Figma community file "Spectral Gradient Vol 2.0" (a near-black indigo field with one violet beam), painted over `--color-bg-hero-image` until it loads and preloaded as the first paint; the final CTA band keeps the Primary 800/900 recipe. Attribute the community file per its licence before launch. Measured on the rendered page at 1440 × 900, the brightest pixel behind any headline word is the beam core (about #2d1c7e), where white is 13.3:1 and the muted ink 9.2:1; everywhere else the field is darker.

Logos: `components/brand/WalaOneLockup.tsx` (bilingual lockup, mark-right for Arabic, mark-left for English, `tone="mono"` follows `currentColor`, `tone="color"` is purple + yellow) and `components/brand/AmazonLogo.tsx` (wordmark follows `currentColor`, smile stays `--color-partner`). The header recolours both through its existing colour tween, so the white reverse over the hero and the colour/black versions on the solid header need no asset swap. `public/brand/*.svg` are the canonical exports (Figma node 6174-1139; Amazon from Wikimedia Commons, public-domain geometry, trademark applies) and the only colour-bearing files outside `tokens.css`; `lint:colors` never scans `public/`.

Contrast (WCAG AA, computed): ink on white 16.5:1, ink-muted on white 7.6:1 and 4.7–7.2:1 on every pastel including hover, white on Primary 800/900 10.8/13.5:1, ink on yellow 10.2:1, white on Primary 600 5.7:1, ok/err text on their washes ≥ 5.2:1, the field placeholder 5.3:1 on the field fill. The field border is the design system's own `border/input` at 1.5:1 on white, up from `--color-line`'s 1.2:1 but still under the 3:1 that WCAG 1.4.11 asks of a control boundary; the label above and the 2.5:1 ring on focus carry the field instead. Lighthouse accessibility is 100 in both locales.

## Artwork

Every former `ImageSlot` placeholder is filled; the component stays so a slot can be emptied again by passing no `src`. `lib/art.ts` is the single map from slot to file and intrinsic size.

**3D illustrations** (`public/illustrations/*.webp`) are rendered, not downloaded: `npm run render:art` opens headless Chromium (Playwright), builds each scene in Three.js with soft "clay" physical materials, a room environment and a tinted contact shadow on a transparent background, and writes a WebP per scene (6 files, 2–14 kB each). Scenes live in `scripts/render/scenes.js`: the three How-to steps (envelope with the six-digit code card, card + lock + green check, phone with a notification) and three hero sprites. The five hero sector tiles are design-supplied line illustrations in `public/tiles/` (the WalaOne coin, a gift box with a discount tag, two hands exchanging coins, a laptop with shopping bags, a hand holding a takeaway bag), converted from the PNGs to WebP with alpha; `ART.tiles` maps them and `HeroTiles` alternates the purple-50 and yellow-50 washes. On a hover-capable desktop with motion allowed, the first tile cross-fades to the design-supplied "WO coin" loop (`public/lottie/wo-coin.json`: 1080 × 1080, 3 s, spin → glint → float) instead of its label and plays it from frame 0 while hovered; `TILE_MOTION` in `lib/art.ts` maps tile to file and crop, and `TileLottie` mounts it only under that query, so touch devices and reduced motion keep the label. Screen textures are drawn on a canvas from the brand SVGs, so the phone screens show the real mark and the Amazon smile with no text, which is why one render serves both locales. Pass scene names to render a subset (`npm run render:art -- rate step2`); lossless PNG masters land in `.render/` (ignored). The camera fits the sampled vertices of each scene, so a scene can be edited without re-tuning framing.

**Hero Lottie** (`public/lottie/hero-illustration.json`) is the design-supplied "Megaphone Loop" (a hand raising a megaphone, two floating discs, three sound waves that draw on and fade), recoloured to the palette: `npm run render:headline` reads the untouched source in `scripts/render/src/hero-megaphone.json`, maps its three colours to tokens by name (ink outlines and the bell opening → `ink`, cyan rim/handle/discs → `accent`, near-white cone and hand → `ink-on-dark-muted`) with the sound-wave strokes overridden to `accent` because dark lines vanish on the dark hero, thickens the strokes ×1.2 for headline size and writes the file. `HERO_LOTTIE.crop` in `lib/art.ts` carries the drawn region and `HeroLottie` shows it through a custom `viewBox`; the headline box is 1.5 em tall and takes that region's aspect. The co-branded phone animation assembled by `npm run render:lottie` from the three hero sprites (base64 WebP layers, 5 s loop) is kept at `public/lottie/hero-cobrand.json` as an alternative: point `HERO_LOTTIE.src` at it and drop the crop. Either way it goes through `HeroLottie`, so reduced motion shows the first frame.

**App mockup** (`components/ui/AppMockup.tsx`) is the About phone: the UI8 kit "Aganta - Mobile App Landing Website UI Kit" node 8803:2881 (an iPhone 14 Pro "Silver" frame over a rounded block of a gradient photo, with the WalaOne home capture inside), rebuilt in the DOM so the capture stays a separate image per locale. `npm run render:about` (`scripts/render/build-about-mockup.mjs`) prepares the node's two images from its raw fills at `.render/figma/about/` (git-ignored): the frame at 3× its drawn width (904 × 1837, 20 kB, transparent screen) and the gradient photo cropped to what the node's rounded clip shows, corners baked, at 2× (725 × 771, 5 kB). `ABOUT_MOCKUP` in `lib/art.ts` carries the files and the node's geometry; the component lays glow, screen and frame out at those proportions inside a box with the node's aspect ratio, so the whole composition scales with the column (480 px wide at most), and rounds the screen in container units so its corners follow the frame's cutout. The screen is the real home capture per locale (`Home - WO - AR` and `Home - WO - EN`, 750 px wide, WebP in `public/app/`, `APP_SCREEN`), object-fit cover because the English capture is 10 px shorter; the alt is the slot title. The kit is a purchased UI8 asset: keep its use within that licence.

**Phone mockups** (`public/mockups/map-phone.webp`, `transfer-phone.webp`, `market-phone.webp`) stand at the foot of the three Benefits cards: the Figma community mockups "Matte iPhone Mockups - 2021 Updated" (the matte iPhone 13 template; node 55977:6896 with the WalaOne map screen for card 1, node 55977:7434 with the points-transfer screen for card 2, node 55977:9066 with the marketplace screen for card 3). Figma's PNG export bakes the page background and the drop shadow in, so `npm run render:phone` (`scripts/render/build-phone-mockup.mjs`, one entry per mockup) cuts each phone out with the template's own silhouette path (kept with the screen mask in `scripts/render/src/<name>.json`, taken from the SVG export), recolours the body — the path the template names "[Change this color]" — from light blue to the card's phone token (`--color-phone-frame`, Primary 200, on the purple-50 card; `--color-phone-frame-warm`, a derived pale gold, on the yellow-50 card; `--color-phone-frame-deep`, a derived Primary 300, on the purple-100 card) in OKLab so the matte shading and the neutral speaker and camera details survive, keeps the top three quarters, which is all the card shows, and writes the WebPs (848 × 1283: 65, 49 and 38 kB). The script's inputs are the nodes' 2× PNG exports at `.render/figma/<name>@2x.png` (git-ignored; re-export a node when it changes). `ART.benefits.cards` marks the entries `kind: 'phone'` and `BenefitCard` fits each bottom-centred into a box 56 % of the card's height and up to 72 % of its width on desktop (60 % and 64 %, capped at 240 px, when stacked, with a 500 px minimum card height), so the phone scales with the card and stays clear of the copy. Attribute the community file per its licence before launch.

**Step animations** (`components/sections/StepLottie.tsx`). Each "How to subscribe" step plays its own looping Lottie instead of a still: the design’s Neo-Brutalism set, one file chosen per step — savings for entering your details, a payment gateway for the payment, a device for opening the app. They arrive in that set’s own bright palette, which belongs to nothing here, so `npm run render:steps` (`scripts/render/build-step-lotties.mjs`) maps every colour to a token in `tokens.css` **by name**, drawing only on the Primary purple and Secondary yellow families; an unmapped colour is an error, and the two source colours that only paint track mattes are mapped too so that stays true. The sources also carry a Duik "Kleaner" rig — a ~15 kB expression on every animated property, repeated dozens of times — which the script strips along with the pseudo-effects feeding it, since the follow-through sits on keyframes that are already baked. That takes the three files from 792 kB to 101 kB and lets the page keep the light player. The box is a reserved square, so a card never shifts while the player loads, and reduced motion keeps the drawing and drops only the movement.

**Form fields** (`components/ui/Field.tsx`) follow the input component of the WalaOne design system (Figma "Singular V1.0.0", node 8636:323410; the sign-in layout at 14685:28021 shows them assembled). The label sits above a 48 px box that owns the border, radius and padding, with an Iconsax glyph leading the input inside it and an example as the placeholder; the rule and the error both sit under the box. The box carries the states because an input cannot style its own container: the focus ring through `:has(:focus-visible)` and the error border through the input's own `aria-invalid`, which is what a server error sets. Three tokens come straight from the system's variables — `--color-field-border` (`border/input`), `--color-field-placeholder` (`text/tertiary`) and `--radius-field` (`radius/150`) — and the OTP boxes take the same two. The system's sample green is its own demo accent, so the checkbox fill and the focus ring stay `--color-brand`. The glyphs (`components/ui/Icon.tsx`) are Iconsax (iconsax.io) Outline — `User`, `Mobile`, `Sms`, and `TickSquare`'s check for the consent box — copied out of the MIT-licensed `iconsax-react` package and inlined, so nothing is fetched at runtime and no dependency is added; they are closed shapes, so they take `fill: currentColor`, and they are `aria-hidden`, so each title is announced on its own. The mobile field takes the system's phone-number variant (node 8629:339487): a country block holding the Saudi flag and `+966`, filling the box's height, divided from the number by the same border and filled with `--color-field-prefix` (`bg/neutral/Primary`). The design draws a country picker; only Saudi numbers are eligible, so the code is static and the chevron is dropped, and the flag leads the code rather than following it, as asked. The box itself is `dir="ltr"` for that field, so the block sits on the physical left in both locales, the way the design draws both language variants, and so its divider falls on the edge facing the number; what follows the block is put back into the page direction, so the glyph leads the text on the same side as every other field’s. In Arabic that lines all three glyphs up on the right; in English the block already holds the inline start, so the number’s glyph leads the text just after it, as the design draws it. The input is capped at `MOBILE_DIGITS` characters and autocompletes as `tel-national`, both because the field is the national part, and `KSA_MOBILE` is that bare `5XXXXXXXX`, which is what the placeholder shows. The flag (`public/flags/sa.webp`) is the Twemoji Saudi Arabia flag (SVG Repo 405595, the Twemoji set; graphics CC-BY 4.0 by Twitter — attribute it per that licence before launch). `npm run render:flag` (`scripts/render/build-flag.mjs`) re-points the viewBox at the flag inside its 36 × 36 emoji canvas, which pads it above and below, and rasterises it at 3× the 24 px it is drawn at (72 × 52, 1.1 kB). The emoji tile's rounded corners are baked into the image, so the page neither rounds nor crops it — cropping to another ratio would cut the shahada — and 36 : 26 lands within a third of a pixel of the 24 × 17.14 the design draws. It is decorative: the code beside it carries the meaning, so it renders with an empty `alt`.

**Merchant and scheme logos** (`public/brands/`, `public/payment/`). The twelve merchants are the ones in walaone.com's "3,500+ service providers" block, in colour: `npm run render:brands` (`scripts/render/build-brands.mjs`) fetches the site's files once (cached in `.render/brands/`, git-ignored), flattens them on white, trims the margins and normalises each logo onto a **square** 320 × 320 canvas. Fitting every logo to one box would make a square mark read far heavier than a long wordmark, because the wordmark only uses a sliver of the box height, so each is scaled to the same _ink area_ instead and only then clamped to the box: a wordmark fills the width, a square mark sits at about 58 % of it, and the two read alike, and writes `public/brands/<id>.webp`; Amazon comes from the local vector in `public/brand/`, and nana is the one soft logo (a 142 px source) until WalaOne supplies a vector. `BRAND_ROWS` in `lib/art.ts` holds the two rows in the site's order and `Brands` repeats each row five times so it overflows the section on any viewport (square tiles are far narrower than the old 2:1 ones, so three copies no longer reached past the viewport plus the marquee travel); only the middle copy is exposed to assistive tech. mada, Visa and the Mastercard circles (as the generic credit card) are SVGs from Wikimedia Commons (public-domain geometry; trademarks apply) on the payment step. They are shown, not chosen: the card is entered on the gateway’s own page, which is where the scheme is decided, so `PaymentMethods` is a list of marks rather than a control. It carries no state and no focus stop, and the flow no longer holds a selected method — `PAYMENT_METHODS` now only names the three marks and their copy.

**Currency.** Every price is drawn with the riyal symbol the central bank published in 2025, never the written abbreviation: Wikimedia Commons `Saudi_Riyal_Symbol.svg`, taken from SAMA's own file and public domain. `lib/currency.ts` holds it as path data rather than a file, because a price appears a dozen times on a page and the glyph must not arrive after the number it belongs to; `Currency` paints it with `fill: currentColor` so it inherits the colour of the text it sits in, sizes it by height since the glyph is taller than it is wide, and gives it the locale's own abbreviation (`ر.س` / `SAR`) as its accessible name, because a drawing announces nothing. Unicode gave the symbol U+20C0 in 2025, but almost no shipping font draws it, so a text character is not an option. The three copy strings that used to spell the currency out — the hero price lead, the plan card's VAT line and the pay button — now carry a `{sar}` slot and render through `Interpolate`, so the symbol appears inside the sentence rather than beside it.
